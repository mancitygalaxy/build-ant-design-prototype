# 证据与交付说明

## 何时读取

需要核对分级或组织问题清单时，读前半部分；需要报告时，再读报告与配图要求。只有交付 HTML 时才执行 HTML 检查。交付形式按用户当次需求，不因评审范围大就自动制作报告。

## 问题记录

使用项目已有清单；局部评审可以直接在对话中表达，不强制另建表。每项保留：

| 内容 | 要求 |
|---|---|
| 对象与操作 | 页面、业务对象、前置状态和实际动作 |
| 当前事实与证据 | 可见结果和可定位的操作记录、截图或其他直接证据 |
| 判断依据 | 用户要求、项目决定、适用规范或明确说明的体验判断 |
| 用户影响 | 对判断、任务、效率或数据保留的影响 |
| 建议与验收 | 应怎样调整，以及什么操作和结果可以证明完成 |
| 结论与边界 | 已确认问题及其优先级、已知规划、待确认或验证受阻；相关例外与缺口 |

DOM 尺寸、滚动、属性、焦点或计数，控制台错误，源码位置和技术根因只在相关且可取得时补充。没有这些辅助信息，不得捏造；需要它们才能下的结论保持未完成。没有新增证据的重复截图不进入交付。

## 证据能证明什么

- 浏览器实际行为用于确认交互；截图只证明当时画面，不能证明返回恢复和服务端持久化。
- 源码可以辅助定位，但不能替代最终视觉与真实点击体验。
- Mock 数据不证明真实模型或外部调用，页面可见结果也不自动证明接口、数据或业务正确。
- 控制台警告只有与当前判断相关时才进入问题清单。
- 数字有本轮可复算来源；规范依据来自当前项目实际版本的一手文档。
- 用户与项目决定说明目标，操作与材料说明事实，两者分别记录。明确取舍不取消已经观察到的数据损失或可访问性事实，也不把通用建议变成产品硬要求。
- 缺少必要授权或完整来源时暂停受影响的结论，不改用旧材料或信息不等价的来源。

## 结论与优先级

项目有既定分级时沿用；否则使用下列标准。优先级只用于已确认的问题，规划、待确认和验证受阻不混入缺陷数量。

| 类别 | 判断条件 |
|---|---|
| P0 | 主任务完全无法完成；输入发生不可恢复损失；目标设备上关键操作完全不可达；错误行为会造成严重的对象或数据误操作 |
| P1 | 新手容易误判状态或下一步；刷新、返回或切换破坏任务连续性；高频核心操作不可见或难以到达；表单错误无法修正；相邻模块对同一状态的处理冲突 |
| P2 | 不阻断任务但有实际影响的文案、层级、反馈或适用规范问题；专项范围内确认的键盘、触屏、无障碍语义问题 |
| 已知规划 | 已确认后续迁移或分期建设；只检查当前入口、文案及直达反馈是否准确 |
| 待确认 | 产品目标、来源版本的适用性或设计取舍尚未确定，需要明确决定 |
| 验证受阻 | 必要来源、权限、环境、服务端证据或关键状态不可用；说明缺口及受影响的结论 |

弃用 API 等技术发现不自动等于体验缺陷：说明适用版本和影响，需要时作为维护建议。官方建议、必要增强与已确认产品要求分开表达。

## 单项问题写法

标题直接写用户遇到的阻碍。正文按“现状与证据 → 用户影响与依据 → 建议与通过条件”组织，相关例外放在对应位置，不要求每项展开成七个小标题。

P0、P1 保留足以复现和判断的完整信息。P2 可以压缩，但仍要有直接证据、明确建议和可观察的通过条件。技术根因未确认时，建议可以指向进一步定位，不写成已证明的修复方案。

例如，刷新后丢失草稿，需要写明编辑对象、刷新前操作、刷新后结果、该对象的保存约定，以及修复后应如何复验。若该对象明确实时保存，则另查保存是否失败，不建议增加伪“未保存”确认。

## 报告内容按用途选择

在对话中讨论时，先给结论与最有影响的问题，保留必要证据和边界。用户要求文件报告时，沿用其形式或项目模板；没有模板时，按读者需要组织：

- 对象、范围、版本及一句话结论。
- 已确认问题、直接证据、影响、建议与验收标准。
- 与本轮判断有关的任务结果、待确认和验证受阻项。
- 有助于安排工作时再给优先级汇总、调整顺序和应保留的设计。

局部报告不强制包含数量卡、完整任务矩阵、规范专章或分阶段改造计划。整体评审也不要求凑固定问题数、固定类别或固定章节。是否需要重做页面、更换技术方案或安排迁移，只在本次问题确实涉及这些决定时讨论。

需要统计时，以唯一问题编号计数，按实际使用的类别列出；不把规划、待确认和验证受阻算作缺陷。问题编号、任务编号、正文、截图和汇总必须一致。报告里保留有实际价值的正常行为，避免后续修改误伤，不为平衡语气而凑“做得对”。

## 配图要求

- 一张图承担一个主要结论。静态问题可用单图，交互问题用前后状态或必要的连续证据。
- 同一问题保持可比较的视口、裁剪和状态；不要把状态差异误作布局差异。
- 标注不遮挡关键操作、错误和数据。多条问题复用同一证据时注明关系。
- 图片有准确的替代文本，图文报告中的证据可放大查看。
- 文件名或说明包含稳定编号、状态和对象，例如 `P1-03-1024-列表右侧裁切.png`；编号形式可沿用项目约定。
- 使用相对资源路径时，交付必须包含资源目录。截图只保存本轮必要内容，处理无关敏感信息后仍须保留判断依据。

## HTML 报告检查

只有本次交付需要图文 HTML 时，才复用 `assets/report-template.html`。模板只是可删改的布局，示例不决定检查范围；未采用的章节与导航一起移除。键盘、触屏等专项内容只在本轮确实适用且已有证据时保留。

模板中的 `data-template-placeholder` 标记用于防止误交付。对应示例、数量和占位证据替换或删除后，才能移除标记；最终交付的标记数量必须为 `0`。仅删除属性、不处理示例内容仍算未完成。

通过仅绑定 `127.0.0.1` 的 HTTP 服务检查最终报告：

- `<html lang>` 与正文一致，只有一个 `h1`，标题层级清楚。
- 桌面与窄屏无页面级横向溢出；表格可在自身容器滚动。
- 所有图片加载成功；图片放大、关闭及焦点返回可用。
- 页内导航目标存在；来源链接直接支持对应结论。
- 报告自身无控制台错误，不加载不必要的外部脚本、字体或样式。
- 示例文字、示例数字、占位截图、无效链接及占位标记都已处理。
- 实际使用的数量、编号、任务结果和建议一致，版本记录能对应受审对象。

可用 `document.querySelectorAll('[data-template-placeholder]').length` 检查占位属性，用图片的 `complete` 与 `naturalWidth > 0` 辅助核对加载。检查结果不能替代对正文和实际画面的回读。

## 最终说明

简要说明关键结论、实际检查范围与限制；生成文件时给出位置，执行外部交付时说明写入与回读结果，不复述整份报告。核对受审对象没有意外变化，保留用户仍需要访问的服务和页面，关闭本轮不再需要的临时资源。
