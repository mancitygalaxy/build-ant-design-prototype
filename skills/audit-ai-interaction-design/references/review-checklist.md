# 交互评审检查表

## 按范围使用

本表提供可选维度和任务示例，不是每次必跑的全套步骤。局部检查选择相关条目，整体评审用覆盖矩阵查漏，复验只检查变化及受影响部分。先读用户决策与项目例外，再构造真实任务，最后按判断需要补充源码、控制台或官方依据。

没有真实状态时不虚构任务；证据不足时不写成确认缺陷。保存、运行和自动保存等动作遵守主说明的数据边界：先确认隔离演示环境或已有真实操作授权。

## 决策与例外清单

存在多项相关决定或例外时，用下表记录；简单任务可直接引用已有决定，不必另建表。规则写到具体对象和动作，不能把局部决定外推成全局规范。

| 来源 | 版本或定位 | 适用对象 | 明确规则 | 例外或不得外推 | 关联 Case |
|---|---|---|---|---|---|
| 用户、反馈表或项目决策 | 日期、行号、链接或文件位置 | 页面、字段、按钮或操作 | 应做什么 | 哪些相邻场景不适用 | J01—J08 |

## 通用维度

| 维度 | 检查问题 |
|---|---|
| 导航 | 当前页面是否清楚；菜单、地址、后退、前进和刷新是否一致 |
| 入口真实性 | 可见入口是否真的可用；规划中功能是否明确标注阶段状态 |
| 信息层级 | 第一眼能否识别任务、对象、状态和主操作 |
| 页面结构 | 区域、留白、滚动容器、固定区域和内容起点是否合理 |
| 表格 | 关键列、固定列、长文本、滚动、分页、空态和异常数据是否可用 |
| 表单 | 标签、说明、必填、校验、错误定位、焦点、保存和取消是否一致 |
| 状态连续性 | 草稿、选中对象、运行结果、页签和筛选是否按业务实体保存 |
| 反馈 | 成功、失败、异步、危险操作和不可见结果是否使用合适反馈 |
| 响应式 | 窄屏是否裁切、遮挡、双重滚动或隐藏主操作 |
| 键盘（条件项） | 按主说明的专项条件检查 Tab、焦点和快捷操作；错误修正、草稿恢复或危险操作涉及的必要焦点仍需检查 |
| 触屏（条件项） | 按主说明的专项条件检查入口发现性与点击目标，包括用户要求、目标设备需要或核心操作依赖 Hover 的情况 |
| 可访问性（按范围） | 按目标设备、明确要求及任务风险，检查相关标签、错误说明、对话框语义和动态播报；不默认扩展完整专项 |
| 设计系统（按需） | 核对实际组件库版本的 API、组件语义和 Token；弃用项说明影响，不自动列为体验缺陷 |
| AI 过程 | 输入、处理中、工具调用、回复、异常和人工介入是否可分辨 |

## 覆盖矩阵

整体评审先设计连续业务任务，再用矩阵检查遗漏；只填写本轮相关的页面和状态。高风险项需要真实操作或明确的排除、受阻说明，不要求全表填满。

| 页面或任务 | 默认态 | 编辑或运行态 | 错误或空态 | 返回与刷新 | 窄屏 | 键盘或触屏专项（如适用） | 长数据 |
|---|---|---|---|---|---|---|---|
| 填写对象 | 通过 / 不适用 / 待确认 / 验证受阻 |  |  |  |  |  |  |

矩阵用于发现漏测，不要求把每个单元写成独立 Case 或独立问题。

## 状态构造参考

只选择与当前判断有关的状态；单张静态来源没有表达的交互，不据此臆造要求。

1. 默认进入。
2. 悬停和必要的聚焦；命中专项条件时再做完整键盘导航。
3. 选择、展开和收起。
4. 新建或编辑。
5. 触发空值、格式错误和异步失败。
6. 保存、取消和再次编辑。
7. 切换相邻对象或模块。
8. 返回、前进、刷新和直达。
9. 使用窄屏、长文本、满列表和空数据。
10. 检查重复执行、一次性限制和恢复方式。

## 连续任务示例

以下示例按产品能力和本轮范围选用，编号只用于定位，不代表必须逐条执行。

### J01 导航与恢复

- 从相关入口进入并检查本轮范围内的菜单。
- 点击规划中或暂未开放入口。
- 直达真实路由和未知路由。
- 在列表与详情间执行后退、前进和刷新。
- 观察选中项、标题、对象和上下文是否恢复。

### J02 新建与错误修正

- 打开新建。
- 空提交。
- 修正第一个错误。
- 制造格式或异步错误。
- 保存并重新进入。
- 观察错误是否就地说明；命中专项条件时再检查自动聚焦。

### J03 连续输入与运行

- 按当前业务约定连续发送输入；只有规则允许时才检查两条输入合并，不默认同属一个 Request。
- 查看处理中、工具、回复和耗时。
- 运行中尝试切页、切对象和返回。
- 等待完成后刷新。
- 观察 Request、结果和恢复边界。

### J04 显式保存草稿

- 进入编辑并修改内容。
- 切换编辑对象、模块、返回和刷新。
- 分别取消离开与确认离开。
- 观察草稿和提示是否一致；焦点仅在直接影响恢复时检查。

### J05 实时保存

- 修改实时保存项。
- 切换对象和模块。
- 重新进入并读取结果。
- 观察是否出现伪“未保存”确认，以及保存失败是否可见。

### J06 批量审核

仅在当前产品有批量审核且纳入本轮范围时采用。

- 进入批量列表和详情。
- 筛选成功、失败、待定和未判断。
- 完成人工判断和备注。
- 打开证据后返回。
- 观察最重要的判断操作是否在首屏可达。

### J07 长数据与窄屏

- 使用最长名称、ID、URL 和文本。
- 填满列表并访问最后一项。
- 切换目标视口。
- 观察截断、Tooltip、固定列、滚动、分页和浮层遮挡。

### J08 键盘与触屏专项（条件执行）

- 按主说明的专项条件执行；目标设备上的核心入口依赖 Hover，或问题也阻断默认操作时，检查相关路径。
- 只用键盘完成主要路径。
- 检查 Tooltip 和隐藏操作能否聚焦。
- 检查拖拽是否有键盘替代。
- 在无 Hover 条件下检查复制、删除和辅助入口。

## 未保存保护判断

| 问题 | 是 | 否 |
|---|---|---|
| 是否需要显式保存才生效 | 继续判断损失风险 | 不建立脏状态 |
| 离开是否会丢失用户输入 | 需要离开保护 | 不弹离开确认 |
| 是否实时保存 | 不制造伪脏状态，保存失败就地反馈 | 按显式保存约定判断离开风险 |
| 是否为同类草稿再次新建 | 可隐藏或禁用新建，避免叠加草稿；沿用明确例外 | 维持入口 |
| 用户是否明确免确认 | 维持例外 | 按风险判断 |

同一编辑器切换对象时，按草稿是否会丢失决定保护方式；取消离开后保留草稿及与恢复相关的焦点。运行任务要说明离开后继续、暂停还是中断，并保持同类任务一致。普通展开、收起和已有清晰结果的操作，不重复打断。

## 反馈选择

下列组件名是常见实现示例，实际沿用项目组件库与产品约定。

| 场景 | 优先反馈 |
|---|---|
| 页面已经清楚显示结果 | 不重复弹全局消息 |
| 字段错误 | 字段附近文字；专项或长表单需要时再聚焦 |
| 轻量成功且结果不可见 | Message |
| 后台任务完成或需要后续处理 | Notification |
| 页面内持续风险或说明 | Alert |
| 必须中断并要求决定 | Modal |
| 简单、低信息量危险确认 | Popconfirm |

## 高风险信号

这些信号用于选择验证路径，不能仅凭命中就确认缺陷。

- 详情状态不在 URL，刷新回列表。
- 全局 `min-width` 配合 `overflow: hidden`。
- 主操作、错误说明或审核列落在屏外。
- `aria-describedby` 指向不存在的元素。
- 目标设备以触屏为主时，关键按钮只在 Hover 出现。
- 命中键盘专项条件时，拖拽是唯一排序方式。
- 固定浮层遮挡分页、输入或保存。
- 运行中离开规则在相邻模块不一致。
- 当前设计系统已经弃用的 API 仍大量存在。
- 规划中入口外观与已开放入口完全相同。

## 视口与复杂评审

按目标设备、最小可用宽度和实际布局变化点选择视口。后台项目可参考 `1024`、`1180`、`1366`、`1440`、`1920` 等宽度，但不要求每次全部覆盖；局部修改优先查相关断点，具体宽度服从项目约定。

复杂任务确有独立工作可拆分，且当前工具与任务允许使用子代理时，可分别检查静态源码、连续任务或目标版本的官方规范。每项明确范围、证据与停止条件，主代理核对关键发现并汇总；不让多个代理重复全面检查，不因使用本 Skill 自动启动分工。
