# 交互体验评审

判断用户能否看懂当前状态、顺利完成任务，并在出错或离开后继续操作。适用于普通后台、AI 产品及不同技术方案的交互原型；AI 过程与组件库规范按当前产品选择检查。

## 分工与交付

- 本 Skill 评审单一对象的体验，默认不修改受审源码、交付文件、研发环境或真实业务数据。
- 对照已确认原型与研发实现，使用 [原型与研发实现差异走查](../audit-prototype-implementation-diffs/SKILL.md)。同一任务兼有体验与对版要求时，分别说明判断依据，共用仍有效的证据。
- 用户要求制作、修改或修复时，使用 [制作与修改交互原型](../build-interactive-prototype/SKILL.md)，按已有授权范围推进。需要处理飞书或企微反馈来源、回写状态时，配合 [处理飞书与企微原型反馈](../iterate-prototype-from-feishu-feedback/SKILL.md)。
- 未要求文件或外部交付时，在当前对话给出结论和问题清单。是否生成报告、采用什么形式，由当次需求和已明确的用途决定；整体评审不自动要求 HTML。
- 用户已要求报告时，按指定形式或项目约定交付；可自行确定不影响用途的文件名和位置。只有格式、读者或目标位置的缺口会改变交付时才询问，不把用户必须提供精确路径作为开始条件。

## 确认对象与范围

先读真实项目的规则、交接卡、指定材料及已有评审方法。单文件没有项目材料不构成阻塞；项目已有方法和明确例外优先采用。

从上下文确认评审对象、可识别版本、用户任务、模块、目标设备和本轮用途。维护源码、构建关系、依赖版本和存储方式只在相关判断需要时补查，不把全工程盘点作为局部评审前提。开始前记录受审文件的版本或指纹，结束时据此检查有无意外改动；远端环境记录可取得的发布或页面标记，不编造哈希。

按用户请求选择深度，不要求用户先选一套固定流程：

| 任务 | 检查范围 |
|---|---|
| 局部检查 | 指定页面或操作，以及会影响判断的关联状态 |
| 视觉评审 | 指定页面、参考图及相关布局状态，区分可见问题与审美建议 |
| 整体评审 | 主要用户任务、跨页面状态、关键异常和目标设备；用覆盖矩阵检查高风险遗漏 |
| 修后复验 | 原问题、新变化和受影响状态，复用仍覆盖当前版本的检查结果 |

已有反馈或问题清单时沿用条目编号与来源定位，补充本次观察和验收结果；不因切换到评审就重建清单。复验先核对原问题的触发条件与当前版本，不把原修复说明或状态标记当成已经通过；只有相关变化或新发现影响其他路径时扩大范围。

先区分两类材料：用户要求、项目决策和适用规范说明“应当怎样”；浏览器行为、截图、DOM、控制台和源码说明“实际怎样”。产品明确取舍不能抹去已观察到的损失，通用建议也不能冒充项目硬要求。存在多项决策或例外时，使用 [检查表中的决策记录](references/review-checklist.md)，只记录与本轮相关的对象和动作。

必要来源、登录态或权限不足时，暂停依赖它的步骤，说明缺口并标记验证受阻；不以旧版本或信息不等价的来源代替。用户指定的材料本来就是静态画面时，只评价可见内容，不据此确认交互和持久化能力。

## 选择任务并实际操作

用户关注配色、主次、质感或视觉参考时，按需读 [视觉参考与效果检查](../build-interactive-prototype/references/visual-design.md)，其中包含参考库索引与本机资料定位方式。参考仅用于借鉴时不按研发对版判错；已有明确验收目标时再使用对版流程。静态评审只评价可见内容，涉及操作或动效的判断仍需实际验证。

按需读取 [交互评审检查表](references/review-checklist.md) 中相关维度与任务示例。整体评审可用覆盖矩阵查漏；局部检查不必加载全部示例或遍历所有菜单。一条任务应覆盖一段有意义的操作，不按页面、截图或固定数量凑项。

优先检查会影响用户判断、核心操作或数据保留的路径：

- 进入、定位对象、输入或选择、得到反馈，再返回或继续。
- 新建、校验失败、修正、取消及必要的保存后状态。
- 切页、切对象、返回、刷新和直达后，上下文是否符合产品约定。
- 长文本、满列表、空数据、异常数据与浮层是否影响主任务。
- 依赖取数的任务，分别观察首次进入、加载中、成功为空、失败与重试；检查前置请求和快速切换，避免把尚未返回误判为无数据。按相关风险构造场景，不因快网络下正常就省略必要状态。
- AI 产品的输入、处理中、工具调用、结果、失败和人工介入是否可分辨；连续输入是否合并，以当前业务约定为准。

需要浏览器时，先读当前可用工具的文档；用户未指定时优先本机 Chrome，回退 Edge。本地 HTML 通过仅绑定 `127.0.0.1` 的 HTTP 服务访问。记录操作前状态、动作、可见反馈及相关的返回或刷新结果，不用截图代替实际操作。

检查宽度按目标设备、最小可用宽度和布局变化点选择，不默认遍历一组固定分辨率。响应式检查要实际改变视口，不能只做整体缩放。键盘、触屏及无障碍专项仅在用户要求、目标设备或明确验收条件需要时展开；核心入口依赖 Hover、同一问题阻断默认操作时，也要检查相关路径。其余情况保留与错误修正、草稿恢复、危险操作直接相关的必要状态检查，不主动扩展专项，也不把未开展专项写成缺陷。

## 操作中的数据边界

“只读评审”包括保护受审文件和真实数据，不等于只能观看静态页面。

- 已确认不连接真实服务、可恢复的隔离演示环境，可以构造输入、保存、运行和恢复状态；保护用户原有浏览器数据，不擅自清空或覆盖。
- 真实系统的保存、创建、删除、发送、运行及自动保存，都可能产生写入或外部影响。操作前核对已有授权、测试数据、影响范围和恢复方式；授权已覆盖时不重复询问。
- 未取得必要授权时停在可安全观察的状态，暂停依赖真实提交的结论，标记验证受阻。自动保存应在修改字段之前识别，不能以“没有点击保存”为由视为只读。
- 不通过修改源码、缓存、业务数据或产品设置来让评审通过。用户另外要求修复时，转入已授权的修改流程。

显式保存、实时保存、草稿切换、重复新建和运行中离开的判断，见 [状态保护与反馈选择](references/review-checklist.md)。以真实损失和产品约定决定是否需要提示或拦截，不把所有操作都改成确认弹窗。

## 取证与判断

先确认实际行为，再按问题补充截图、DOM、控制台、源码或官方依据；这些是可选证据类型，不要求每条全部具备。只有证据支持时才写技术根因，缺少源码不妨碍描述已经观察到的体验问题，但不能据此声称根因已确认。

截图只证明当时画面，页面内存状态不证明服务端持久化，源码不替代真实操作，前端 Mock 不证明模型、Agent、MCP 或外部业务已经可用。控制台警告只在与本轮判断相关时记录。数字必须来自本轮可复算数据，例如以 `scrollWidth - clientWidth` 计算溢出宽度。

视觉评审分别判断构图、色彩累计面积、图形选型和表面层级，指出仍未解决的具体差距；功能、对比度与无溢出检查不能替代这些判断。用户否定观感时，记录对应版本与未获认可的具体范围，不用已通过的操作检查反驳视觉反馈，也不把某一色相改成通用禁用规则。

需要核对设计系统时，使用当前项目实际版本的一手文档，区分明确冲突、官方建议和产品取舍；不因使用本 Skill 自动转向 Ant Design。

观察到加载慢或操作卡顿时，记录动作、起止条件、样本规模、首次或重复访问、浏览器及测量证据。区分可见等待、同条件耗时和已证实的原因；服务端缓存未知时写明，不能把浏览器首次访问当作服务端冷启动。证据不足时说明下一步如何验证，不凭框架或数据量猜根因。

## 整理结论与复验要求

已确认同一原因、改法和通过条件的问题可以合并；原因未明时按可观察的行为保留，不猜根因来凑合并。能独立修改或复验的问题分别列出。结果分为：

- 已确认问题：`P0` 为主任务完全阻断、不可恢复损失或严重错误操作；`P1` 影响核心判断、任务连续性或高频效率；`P2` 为有依据且不阻断的一致性、反馈或适用规范问题。项目已有分级时沿用。
- 已知规划：已经确认分期建设或迁移，不计当前缺陷；仍检查当前入口是否准确表达能力。
- 待确认：目标或产品取舍尚未确定。
- 验证受阻：目标可明确，但因权限、材料、环境或关键状态不可用而不能完成验证。

每个问题写清现状、证据、用户影响、判断依据、建议和可观察的通过条件；相关的决策例外一并注明。低优先级可以简写，但不能只写“优化一下”。详细分级与表达参考 [证据与交付说明](references/evidence-and-report-contract.md)。

## 完成与交付

结束前核对本轮范围、版本、证据和结论是否一致，区分已完成、待确认与验证受阻。同一次任务涉及多个 Skill 时共用检查结果；只有版本、相关状态或前提变化，或旧证据不足时才重做对应检查。

按当次需求交付。需要文件报告时，读取 [证据与交付说明](references/evidence-and-report-contract.md)；需要图文 HTML 时才使用 [报告模板](assets/report-template.html)，按用途删改章节并完成报告自身的浏览器验收。不能为了填模板补造问题、数量或专项结论。没有确认问题时如实说明已检查范围和限制；待确认与受阻项不填入缺陷数量。

检查受审文件没有被意外改变。关闭本轮临时验收资源，保留用户原有资源及仍需访问的交付服务。简要说明关键发现、实际检查范围、未完成项和交付位置；只有生成文件或执行外部交付时才报告相应结果。发布、外部写入或发送须有对应目标与范围的授权，已有授权不重复询问。
