# 企微反馈读写

用于企业微信智能表格中的原型调整反馈。链接含 `/smartsheet/`；用户称“企微多维表格”时也按智能表格处理。普通 `/sheet/` 链接按 `wecom-unified` 的在线表格能力处理，不套用本文件的记录接口。

## 入口与字段

先读取当前安装的 `wecom-unified/SKILL.md`，按其要求核验 CLI 版本和授权。具体命令、参数与权限处理以该 Skill 的当前参考资料为准，不在本文件复制整套 CLI 手册。

- 定位及读取：`wecomcli-smartsheet.md`、`wecomcli-smartsheet-read.md`、`wecomcli-smartsheet-field-types.md`。
- 状态回写：另读 `wecomcli-smartsheet-edit.md`、`wecomcli-smartsheet-record-values.md`；使用筛选条件时读 `wecomcli-smartsheet-view-types.md`。
- 只给表名时，按 `wecomcli-doc-manage.md` 搜索；出现多个确有歧义的候选时再让用户选择。

用 `smartsheet sheets list` 定位子表，再用 `fields list` 读取字段及选项。按真实列名映射模块、当前情况、调整要求、截图、优先级、状态和处理说明，不要求用户改成固定表头，也不擅自增加字段或视图。

“是什么情况”描述当前表现或使用场景，“要怎么改”描述目标表现；单独列出的截图与参考链接仍须读取。状态允许值从当前字段取得，不固定假设为“已完成”。

读取待处理反馈时也检查新填但状态为空的记录，按用户本轮范围纳入，不把空值当作已完成或直接漏掉。

## 记录与截图

文字和定位信息优先用 `records query`：在 SQL 中限定本轮模块、状态等条件，显式选择 `RECORD_ID` 与所需字段，并处理完整范围内的分页。SQL 用真实子表名和字段名。返回 `values` 的元素可能是 JSON 字符串，也可能已解析为对象；按实际结构读取 `rows`。

`records query` 对图片、附件通常只返回文件名。需要原图时，使用 `records list` 的相同范围筛选与分页取得记录值，按记录 ID 对应条目，读取 `imageUrl` 或 `fileUrl`。文本值可能是富文本片段数组，需保留各段文字和链接，不能把整个数组直接当字符串。

通过真实返回的图片地址取得原图并查看，下载工具与鉴权沿用当前企微能力；仅当返回真实媒体标识时才走媒体下载，不能把图片 URL 或图片单元格的 `id` 当成 `media_id`。图片不可访问时明确受影响条目，不依据文件名猜测内容。工具缺少原图读取能力且权限正常时，可按本机规则在浏览器读取同一原始表格；权限缺口须先恢复，不能用浏览器绕过。

`records query` 返回 `538005` 时，按企微读取规范降级到 `records list`，完整读取本轮可见范围并保留筛选与分页边界；不能将可见部分宣称为整表。子表访问失败时先重查子表列表，再按企微 Skill 处理，避免盲目重试。

## 写回原记录

原型修改和验收仍由 `build-interactive-prototype` 完成。回写前重读目标记录及状态选项，核对条目内容、截图、模块、当前状态和可用编辑时间；不把行号或显示顺序当作记录身份。

`records update` 使用原记录的 `record_id`，`values` 的键为真实 `field_title`，只包含本轮已授权回写的列。单选状态的值为当前选项对象数组，例如 `[{"id": "<最新真实选项标识>", "text": "<对应状态文本>"}]`；禁止自造选项或顺手新增状态。请求成功后重读同一记录，核对状态及其他原始字段，不能只凭退出码或写接口成功定案。

如果新增或更新记录返回 `851003` / `no authority`，停止重复调用，按 `wecomcli-smartsheet-webhook.md` 核对兜底条件。Webhook 仅能更新此前由该方式写入的记录；人工填入或普通 API 创建的原反馈不能据此更新。此时保留本地已验收结果，说明回写受阻，不新建替代反馈行，也不索取无法用于该记录的 Webhook。

结果未知时先回读；回读缺少证据时保持未确认。只读任务、建反馈表或用户尚在填写反馈，都不自动触发原型修改、状态回写、发布或消息发送。
