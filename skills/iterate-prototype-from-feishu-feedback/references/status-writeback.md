# 状态写入与冲突处理

只在本轮任务包含状态回写时读取。页面实现及验收标准由 `build-interactive-prototype` 统一维护；这里核对哪些反馈具备完成依据，以及如何准确写回。

## 写入前逐条核对

完成条目应能对应：

- 当前反馈内容、模块、允许的完成状态和稳定定位信息。
- 已核对的实际交付版本或文件；有修改时确认交付已更新，需要构建的工程已经构建，直接维护的静态文件已验证当前内容。无需修改时保留已有实现满足要求的本轮证据，不虚构改动。
- 该问题对应的真实页面操作、预期结果及证据。
- 主 Skill 对相关代码质量和必要性能检查的通过结论，或说明某项检查为何与本条无关。
- 未完成、受阻或仍有冲突的部分。

以下情况不能标记完成：只改代码未更新交付、只加载页面未检查对应操作、相关控制台错误未解决、必要测量受阻或不可比较、新增退步未修复、反馈在执行中发生冲突性变化。没有实际要求构建的工程，不人为增加构建步骤。

一个来源记录含多个要求时，整条完成须覆盖其中全部验收点。只完成部分时，按原表已定义的部分完成状态处理；没有合适状态就保留未完成，并在已授权的处理说明或本地清单中说明进度，不能因为其中一项通过就把整条改成完成。反馈已失效、被撤回或需求变更时，按最新来源确认后续处理，不将其伪记为已修复。

## 重新定位并检查冲突

写入前重新读取目标行、区块或记录，核对问题原文、模块、当前状态、状态列及修订信息。表格排序或插行后重新定位，不沿用旧行号盲写；没有唯一定位依据时先解决歧义。

无关区域改变引起修订号变化时，重新核对目标即可。目标问题或范围变化时，重新判断原验收是否仍适用；无法确定时保留原状态。用户或他人已标记同一完成状态时，回读确认并记录，无需重复写入；状态被改成其他含义时先查明原因。

## 电子表格

1. 通过最新表头定位状态列，读取目标单元格值和 `data_validation`，即允许值与校验规则。
2. 确定当前精确写入范围，用支持的 `--dry-run` 或等价预览确认。所用接口没有预览能力时，以已读取的目标和值形成可核对的写入清单，不虚报预览成功。
3. 默认只写状态值；用户另行要求更新处理说明等结果列时，将这些列明确列入本次写入范围。保留原数据校验、样式及未获授权的列，不把整行回写代替单元格修改。
4. 写后核对实际范围 `actual_range`、行索引 `row_indices`、列索引 `col_indices`、状态值、数据校验与最新修订。具体字段以接口返回为准，缺失的信息通过重新读取目标核对。
5. 部分成功时只确认已回读的部分，其他条目继续保持未完成。

## 云文档表格与多维表格

Docx 使用稳定区块 ID，Base 使用记录 ID 与字段 ID。写前核对当前内容和允许值，写后重新读取同一目标，确认只改变预期状态。不能把整份文档替换当作状态更新。

## 企微智能表格

按 [企微反馈读写](wecom-feedback.md) 操作。用真实记录 ID 定位，用字段名称构造 `values`，不能把飞书 Base 的字段 ID 写法套到企微接口。单选状态使用最新字段返回的选项 ID 和文本。

写前重新核对原文、调整要求、截图和当前状态；接口没有修订号或原子条件更新时，对比最新内容和编辑时间，不虚报已实现并发锁。写入后重新读取同一记录，确认只改变授权的结果列。已有“处理说明”需要更新时同样检查冲突，不覆盖其他人的新补充。

出现 `851003` 或 `no authority` 时停止重复 CLI 写入。Webhook 不能更新人工或普通接口创建的记录；不能通过新建一条记录来冒充原反馈的状态回写。

## 中断与结果未知

请求超时、连接断开或返回不明确时，先重新读取目标确认是否写入。已写成功的不重复操作；确认未写且仍符合原范围时再重试，不能根据本地退出码猜测远端状态。

授权缺失时暂停受影响步骤，请用户介入。回写失败不影响已经核实的本地修改结果，但两项状态要分别报告。发布另按具体目标和授权执行。
