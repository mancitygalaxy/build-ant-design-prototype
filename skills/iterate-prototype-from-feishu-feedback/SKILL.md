# 处理飞书与企微原型反馈

负责把飞书反馈与本轮处理结果对应起来：读最新反馈、确定条目和范围、保留来源，再准确回写已验证状态。原型制作、代码修改、页面与性能检查使用 [制作与修改交互原型](../build-interactive-prototype/SKILL.md)，本文件只规定反馈处理要求。

## 先确定这次要做什么

- 只读或整理反馈：读取正文、表格和相关截图，输出指定范围的问题，不修改原型或状态。
- 按反馈修改原型：整理条目后，使用 `build-interactive-prototype` 完成修改与验收，再回写本轮验证通过的状态。
- 只回写已有结果：先核对反馈最新内容、实际交付版本和对应验收证据，再写已验证的条目；不能仅凭“代码已改”或旧口头结论标记完成。

用户明确要求按本 Skill 完成反馈修改流程时，状态回写属于该流程；单纯提供链接或要求读表不代表写入授权。已有授权明确时不重复询问。

## 恢复来源与范围

先读项目规则、交接卡和本轮上下文，补齐反馈链接、目标原型或源码、本轮模块、参考原型、完成状态。完成状态以状态列的数据校验和用户口径为准，不固定写成某个词。

用户只给“反馈链接 + 目标原型”时，先自行查找项目入口及反馈结构；仅剩余缺口会改变范围、实现或回写时，集中询问。中断后继续要重新读取来源内容、核对目标版本和已有授权，避免重复处理或重复写入；已有授权仍明确有效时不重复询问。

- 只处理本轮指定模块。未指定时，只有一个待处理模块可据此继续；多个模块会明显扩大范围时先询问。
- 执行中新增或修改的反馈重新读取；只纳入当前范围，不顺手处理其他待办。用户缩小范围时立即以最新要求为准。
- 缺少必要来源或授权时暂停依赖它的步骤，不改用截图猜测、浏览器抄录或信息不等价的来源。
- 原型修改与必要验收资料由主 Skill 核对；找不到主 Skill 时可以继续读取和整理反馈，先说明缺失再处理修改步骤，不另起一套简化验收。

## 读取最新反馈

按资源类型使用当前可用的能力，并读取对应 Skill：

| 来源或动作 | 对应能力 |
|---|---|
| 飞书认证与权限 | `lark-shared` |
| 飞书 Wiki 节点解析 | `lark-wiki`，解析真实对象后继续读取 |
| 飞书电子表格 | `lark-sheets` |
| 飞书云文档与文档表格 | `lark-doc` |
| 飞书多维表格 | `lark-base` |
| 飞书图片或附件 | `lark-doc` 或 `lark-drive` |
| 企微智能表格（也称多维表格，链接含 `/smartsheet/`） | `wecom-unified`；先读 [企微反馈读写](references/wecom-feedback.md) |

可用 CLI、连接器或 API 能完成语义读写时，优先使用它们。浏览器用于原型验收或工具确实无法完成的已授权界面操作，不能用于绕过权限缺口。

读取表头、目标模块、问题、状态、允许值、真实行列位置和修订信息；文档表格保留区块 ID，飞书多维表格和企微智能表格保留记录 ID。下载并查看相关截图和附件，不能只读文字；只返回文件名不算已读图片。

将“是什么情况／当前表现”与“要怎么改／期望结果”分别保留，不混成同一段要求。缺少独立字段时从原文整理，不能把自己的推测当作用户要求。新增需求、已有问题和补充说明都按实际内容处理，不因表名含“问题反馈”就一律当作 Bug。

对话中新确认的目标与旧表述冲突时，在本地原条目中标明最新决定、来源和已替换内容，重新核对验收条件。外部调整要求、说明或截图已获更新授权时修改对应原记录；仅授权状态回写时列出待更新内容，不扩写其他列，也不为同一变化重复建需求。

复用项目问题清单，每条保留：

- 来源链接，真实行号、区块 ID 或记录 ID，以及当前修订信息。
- 模块、问题原文、当前状态、截图或附件。
- 当前表现、目标表现及能观察到的通过条件。
- 本轮处理情况、交付版本和验收依据。

已有本地清单、评审或对版条目时沿用编号，把同一来源记录与本地验收点对应起来，不为切换 Skill 重建需求或复制反馈表。一个原记录含多个要求时可在本地拆分验收点，保留共同的来源记录身份；不擅自拆写远端原记录。

行号、列字母和固定文件名只用于本次定位，不作为长期身份。用户说“表格更新了”或“继续”时重新读取，进度简写为“正在读取最新反馈”；发现冲突或内容缺失时说明具体问题。

## 将问题交给原型制作流程

需要修改时，把已确认的条目、截图、参考原型、模块范围与验收条件交给 `build-interactive-prototype`，沿用真实工程技术与交付方式。这里的“交给”指使用同一任务中的主 Skill，不自动创建聊天或子代理。

按条目核对主 Skill 返回的变化、最终交付版本、实际验收动作、相关质量与性能结果、证据位置及剩余问题。复用仍覆盖当前版本、数据和操作状态的结果，只重查失效或缺失部分，不因反馈来源或阶段切换重跑一套。已有实现经本轮核对已满足要求时，记录“无需改动”及依据，不为了证明处理过而改代码；能否写为完成仍以原表状态含义和全部验收点为准。

源文件、当前页面或反馈发生变化时，只重查受影响部分。构建或验收失败时继续完成范围内的修复，相关条目保持未完成，不提前回写。

## 回写与回读

回写前读 [状态写入与冲突处理](references/status-writeback.md)；用户要求同步需求文字或前后截图时，同时按其中的材料更新要求核对。重新读取目标记录，核对条目内容、模块、位置、状态和修订；存在冲突时暂停该条写入，其他无冲突条目可以继续。

默认只写本轮已验收条目的处理状态。用户同时要求回写“处理说明”等结果列时，只在授权列补充实际改动、验收结果或未完成原因，保留已有有效内容。保留问题描述、调整要求、截图、模块、其他列、样式及数据校验；额外修改这些内容需要用户明确要求。写后回读实际目标与状态，结果未知时先查询，不盲目重试。

本地交付、状态回写和远端发布分别记录。上传、回推、部署或发送消息需要对应授权；发布使用项目正式入口并完成远端核对，不绕过白名单或正式脚本。

## 完成说明

先说本轮结果，再简要给出已处理条目、交付位置和验收结果、状态写入及回读结果、未完成项。只完成读取时交付问题清单；部分条目完成时区分已回写、未完成和冲突项。只有实际执行发布时报告发布结果，不把本地检查或回写状态当作发布完成。
