# 沿用已有原型与适配新业务

修改已有原型、复用旧产品或适配新业务时读取。沿用项目现有技术、目录、检查与交付方式；本轮变化以用户已经确认的需求为准。局部修改围绕受影响模块，不顺带改造整个工程。

从源码生成的交付文件先反查维护工程。只有确认不存在维护源码、用户明确同意且仍可可靠验证时，才直接编辑构建后的文件。纯手写 HTML 本身可以是维护源码。

## 确定各类来源负责什么

从上下文及项目入口中恢复以下信息，只追问会改变实现或验收的剩余缺口：

| 对象 | 需要确定的内容 |
| --- | --- |
| 本轮交付 | 使用者、用途、要改变的行为、明确保留的部分、交付形式 |
| 业务来源 | 需求、指标或字段定义、用户已经确认的变更、仍待决定的口径 |
| 交互基线 | 哪个产品及版本提供布局、样式、状态、保存、排序和记忆规则 |
| 数据来源 | 样本条件、时间、适用范围、缺失语义，以及可否复用旧数据 |
| 当前实现 | 实际工程、运行入口、源码版本和正在看的页面版本 |

用户明确确认的变更优先于旧基线。区分“沿用旧版”“已确认差异”“实现缺陷”“待确认”，避免把合法的新需求当成还原问题。待确认的业务规则不得自行固化为临时默认值；用户明确允许假设时，记录假设及替换位置。

截图只证明其展示的状态。没有交互依据时，不猜失焦、取消、重开等行为。必要来源、权限或环境不可用时，暂停依赖它的判断和改动，说明缺口；可以继续不依赖该来源的工作。

## 先判断复用方式，再写实现

先查原组件、样式、纯函数、状态所有者及其依赖，再选择适用路径：

| 条件 | 优先做法 |
| --- | --- |
| 含义、交互与运行依赖相同 | 直接共用原实现，避免复制后分别维护 |
| 呈现相同，字段、来源或业务规则不同 | 共享呈现和交互，使用适配层转换数据与规则 |
| 有明确的新行为或原版缺陷 | 保留适用部分，单独实现确认的差异并列入验收 |
| 环境不同、源码无法使用或依赖不适合抽取 | 记录限制，依据已核验的设计和行为重新实现；不宣称已经代码复用 |

接入共享实现时核对输入与事件约定：稳定标识、层级从哪里开始、空值与零值、格式及单位、分子分母、排序方向、保存时机和取消结果。组件能显示出来不足以证明这些约定正确。

沿用旧数据前核对定义及统计范围；名称相近或页面有值不足以证明同口径。生产权限、旧系统写入和对外发布不会因代码复用而自动获得授权。

## 把检查放进实现过程

在已有计划或问题清单中记录“当前事实 → 目标行为 → 修改方式 → 可观察的通过条件”，无需仅为使用 Skill 新建报告。每次用户指出问题，都检查同一原因是否影响相关状态和入口，并保留已确认的业务差异。

按实际模块选择检查范围：

| 模块 | 重点状态和操作链 |
| --- | --- |
| 筛选、搜索 | 默认、全选／半选／空选、联动重置、清除、刷新后的记忆、请求先后返回 |
| 日期、阶段 | 查看与编辑、键入与选择、起止边界和衔接、无效输入、取消、切换与推荐值 |
| 表格、列表 | 分组与排序、聚合或展示口径切换、层级展开、冻结与滚动、悬停叠加底色、长内容、缺失值与汇总 |
| 视图、配置 | 新增、复制、改名、删除、排序；带草稿切换、失焦后直接操作、保存后重开、失败后恢复 |
| 字段库、帮助 | 搜索命中与别名、分类计数和滚动、显隐与顺序、字段说明和实际格式 |
| 复制、导出 | 实际结果中的字段、层级路径、单位和数值，而非只看成功提示 |

重点走完相邻动作，例如“改名后直接切换”“有字段草稿时复制”“保存后关闭再打开”。先确定哪些状态应保留或重置，再检查实现；不要默认所有切换都必须保存状态。

异步操作按风险检查重复点击、旧响应覆盖、保存失败和重试。零值、缺失、无样本、无权限、待配置按业务定义区分。合成边界数据放在隔离测试环境，不混入真实样本或用户已保存配置。

## 用页面和代码分别验证

- 使用可比的窗口、缩放、筛选和页面状态对照；数据不同但不影响某项比较时说明原因。
- 在浏览器实际触发悬停、聚焦、展开、保存、切换和重开。源码用于核对隐藏规则及解释行为，不能替代这些实际操作。
- 修改共享实现后，检查所有受影响的使用方；尤其回归旧版入口和新业务入口。
- 根据改动执行必要测试与项目要求的工程检查。局部视觉修改验证关联状态；状态和数据改动补充有意义的行为或边界测试。不要为了增加测试数量编写只复述实现的测试。
- 对最终候选执行本轮验收清单，确认页面来自当前源码和构建。无相关改动且证据仍有效时复用结果，不机械重复整轮检查。
