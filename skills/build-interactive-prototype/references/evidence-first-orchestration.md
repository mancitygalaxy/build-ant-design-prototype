# 协作与检查结果复用

用于跨模块变化、复杂分工或需要汇总多份检查结果的任务。简单局部修改无需读取本文件。

## 记录什么

复用现有计划、派单和检查回执，记录“检查哪个版本和状态、要排除什么问题、怎么检查、结果是什么、下一步怎么处理”。每个待解决问题保留一条，不为填表另建文件或反复计算哈希。

现有源码版本、构建记录或交付哈希能够区分对象时直接使用。记录失败、缺失和工具限制，不能把未检查当作通过。

反馈、体验评审、原型对版和修复在同一份清单接续：保留来源定位、条目编号、当前事实、目标与通过条件。阶段切换只补本阶段的发现、交付版本和操作结果，不另造编号或重复报告。来源目标改变时明确变化；旧证据只在仍支持本条结论时沿用，不能靠本地勾选“已完成”替代实际复验。

## 什么时候可以沿用结果

以下条件同时成立时，可以复用已有结果：

- 检查对象及本次关注的内容没有变化，能说明结果仍适用于最终版本。
- 要排除的问题、检查方法和通过标准相同。
- 页面宽度、输入数据、环境和操作状态相同。
- 上次结果完整可读，没有影响该结论的工具限制。
- 中间没有相关修改或外部变化，本次也不承担独立复核任务。

上述条件由本次要回答的问题决定，不要求无关内容逐字节相同；但同一构建号、文件哈希或截图本身不能证明操作状态、数据与环境都未变。复用时说明覆盖哪些条目或操作即可，不反复生成指纹或重做完整链路。

只要相关条件变化，就重查受影响部分。没有发现问题但排除了明确风险，也属于有效检查；无关代码变化不要求全部重跑。

## 如何分工

是否使用子代理服从当前工具能力和授权。以能够独立完成的工作为依据分工，不固定人数，也不把同一份“全面检查”派给多个人。

可以分开的任务包括源码结构、状态与保存规则、视觉与响应式、实际操作、构建及交付来源。每份任务说明：

- 要回答的具体问题。
- 相比已有工作能新增什么依据，结果会影响什么决定。
- 可以读取和修改的范围。
- 得到什么结果后停止。

不同组件边界清楚时可以并行修改。共享状态、全局样式或同一文件同一时间只有一个写入者。实施期间，复核者可以先准备数据和检查路径。

高风险变化保留必要的独立复核。普通任务可以由同一执行者完成不同检查，但源码、截图、实际操作和构建分别承担的检查责任仍需落实。子代理返回新增事实、缺陷和来源，主执行者核对关键结论，不重新跑完整过程。

## 哪些结果不能互相替代

- 源码检查不能证明浏览器呈现正确，类型与构建通过不能证明实际操作可用。
- 截图显示外观，浏览器计算后的样式用于定位具体样式问题。
- 默认、悬停、选中、展开、收起和禁用是不同状态；普通宽度与最小目标宽度也分别检查。
- 修复前复现用于确认问题，修复后检查用于确认解决。
- 定向检查完成后，仍要核对最终版本是否有失效或遗漏的检查。
- 源码工程可运行不等于打包文件完整；本地正常不等于远端发布成功。

不要为了形式增加无关检查。范围、条件与结果完全相同时复用已有依据；需要不同依据的问题分别处理。

## 反馈与发布

相互独立且方向明确的反馈可以一起修改；后一项依赖前一项实际效果时按顺序处理。目标、来源或交付物改变时重新确定范围，只有用户要求时才创建新聊天。

工具调用数、上下文长度和代理数量用于判断是否有重复工作，不用于提前停止必要检查。

取得明确发布授权后，发布已检查的候选版本，再从远端核对版本、页面加载、关键入口和至少一条主要任务。记录发布目标与结果，不以本地检查代替远端确认。
