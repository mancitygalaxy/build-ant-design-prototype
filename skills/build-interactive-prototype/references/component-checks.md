# 组件制作与页面检查

涉及对应组件时读取，组件名称和具体接口以项目实际组件库为准。本清单补充具体做法；检查范围按本轮变化确定，局部修改不逐项执行全部内容。Ant Design 的组件属性、样式变量与动画处理见 [Ant Design 制作分支](ant-design.md)。

## 框架、品牌和菜单

使用标准组件可以复用它的交互，但仍需检查是否符合当前设计。

- 优先使用已确认的 Logo、SVG、字体和布局。缺少品牌资源时说明临时替代，不将其报告为已对齐。
- 有视觉参考时，明确顶栏、侧栏、菜单、字号、间距和各状态样式；没有参考时形成一致方案，不要求用户逐一批准默认值。
- 排查布局和菜单样式时，依次检查组件公开属性、主题与组件变量、局部 CSS 和浏览器计算后的样式（`computed style`）。
- 样式变量尽量只作用于目标组件，避免一处菜单调整影响账号下拉等其他区域。响应式规则不能破坏已确认的布局。
- 框架变化后，检查默认、悬停、选中、子菜单展开、侧栏收起和下拉打开状态；核对宽高、背景、文字、字号、字重、间距、圆角和图标尺寸。
- 收起侧栏时检查图标是否居中；打开下拉时检查菜单项、禁用原因和点击反馈。指针经过相邻区域时，检查边框、阴影和过渡是否闪烁。

展开、收起或选中闪烁时，检查组件状态、隐藏样式与实际可见性，定位不应显示的旧节点或具体过渡属性；保留正常动画。

## 组件选择和同类控件

按用户操作的含义选择组件。例如，切换页面内容、选择一个配置值、切换展示模式分别判断，不因界面都有多个选项就使用同一种组件。

多个配置区需要联动时，可以组合项目已有的标准组件；状态由明确模块统一管理，具体选型服从操作含义。

同类控件按用途识别，不只按组件名识别。例如下拉选择与级联选择都用于选择配置时：

- 统一字段标题是否出现、控件高度、字号、内边距、边框、圆角，以及悬停、聚焦和禁用状态。
- 两处以上重复时，优先复用字段容器、共享样式或局部 token。
- 确有不同需求时记录业务理由，并检查这种差异是否容易理解。
- 比较所有相关场景，避免只修当前看到的一处。

## 表格与筛选

设计表格时先确定列宽、折行或截断、固定列与滚动方式，再用真实长度的数据和最小目标宽度检查。

- 补充截断文字的 `Tooltip` 只在实际溢出时出现；帮助说明类提示按业务需要保留。
- 高密度列表检查分组箭头、横向与纵向滚动、分页联动和整行悬停。
- 固定列的背景、悬停和分隔投影应连续；没有遮挡内容时不常驻投影。
- 轻量、可撤销、无需等待的本地筛选优先即时生效，同时更新列表、已选数量和分页。
- 多条件组合、远端请求或高成本查询可以保留“应用”；采用哪种方式以实际操作成本和产品约定为准。

## 异步区域与首次加载

涉及取数、筛选切换或详情加载时，检查完整依赖链；身份、范围或配置仍在加载时，不能提前显示成功空态。优先复用基准已有的加载组件和反馈样式。

- 加载中：保留可理解的区域结构；尚未知的数量不显示为零。是否保留旧结果及如何标识，以产品约定为准。
- 成功有数据与成功为空：必要请求完成后再判定；样本未采集不等于业务为空。
- 失败：有明确反馈和可用的恢复方式，超时按项目条件设置，避免永久空白或转圈。
- 切换与重试：检查快速切对象、请求乱序和重试后旧响应，不让前一对象的结果覆盖当前对象。
- 按影响实际构造首次进入、慢响应、成功空结果、失败和重试；故障构造使用隔离环境或已授权的测试入口。涉及长连接时再检查断开与恢复，不扩展成每轮必跑的全套网络测试。

## 表单、弹层与反馈

同一对象的新建与编辑优先共用表单结构和校验规则。哪些字段可以修改由业务要求决定；不可改字段保留原值和必要的展示，提交只更新允许修改的字段。

- 分别检查新建、编辑、取消、重复提交和失败恢复；核对字段位置、权限及保存结果。
- 弹窗标题下的辅助说明用于补充影响范围、前提、风险或恢复办法，不固定添加复述标题的小字。
- 复制、展开、切换等结果已经可见时，优先给局部反馈；保存、失败和不可见异步结果需要明确提示。
- 关键操作检查键盘可达、焦点可见、弹层关闭后焦点去向，以及字段与错误提示的关联。
- 检查窄屏、长标签和长错误信息，避免遮挡、双重滚动或主要操作移出可用区域。
