# 视觉参考与效果检查

用于新建视觉方向、视觉改版、按图借鉴或只读视觉评审。按本轮范围选用；局部文案、功能修复和保持外观的代码整理，不重新选择风格。

## 先分清要求与参考

- 用户要求与项目决定说明目标；原作中实际看到的内容属于参考观察；具体色值、布局和实现参数属于方案选择。把三者分清，不将助手建议写成用户偏好。
- “浅色”“整体好看”等评价不自动确定色相、饱和度、主色数量或整套布局。参考库的配色和 tokens 是候选，采用时结合当前任务、品牌与设备判断。
- 记录认可的对象和范围。“上半部分不错”只确认对应区域；本轮保留它，调整指定部分。不得据此宣称整页、其他页面或所有项目已获认可。

## 选参考并实际看图

优先使用用户指定来源。未指定时，可按任务、设备和信息密度从已有库选择主要参考，必要时补充其他案例；不要求固定数量或每次重看全库。读取选中案例的说明并实际查看图片，写清准备借鉴的关系及业务适配理由，简短记录在当前方案中即可。

工作区已有 `设计参考/` 时，按项目交接卡或资料索引核对当前试验的版本、认可范围与验证边界；随包原图与视频可跨设备查看，其他本机原型与运行记录不随包分发。缺少用户指定来源时说明缺口，暂停依赖它的判断；可选本机库不存在，不影响已有明确设计的工作。原作素材用于学习评审，产品使用自有或明确可用的素材。

## 从参考到实际页面

- 先指出当前版与参考之间具体的可见差距，再选择改法。借鉴主次、区域比例、阅读顺序与疏密，不能把“合并主卡、换主色、加玻璃或图表”本身当成改进结果，也不为接近展示图删减必要信息。
- 方向不清或改版范围较大时，先用实际中文文案、典型数值和必要状态做好代表页。检查大块区域的分量、标题与正文的尺度、内容密度和空白是否形成清楚的阅读顺序，再扩展到其他页面。按当前共创约定收敛方向；已明确且获授权的部分直接推进。
- 将品牌、交互、业务状态和数据颜色按用途区分，同时看整页累计的色彩面积。某色分别进入导航、文字、背景和大图形后，可能压过中性色与冷暖对比；不能仅因每个局部都有用途就保留。按当前内容与参考调整，不规定所有项目的主色占比或禁用某一色相。
- 先确定图形要帮助用户比较、识别变化、看构成还是定位状态，再选择形式和面积。存在真实数据不等于适合加图；大片高度接近的柱、规则点阵或重复进度条，可能比数字更费解。若图形没有增加判断价值，改用更合适的表达或保留数字，不为凑视觉丰富度给每张卡补图。坐标、比例与缺失语义仍须准确，不为增强视觉差异截改数据。
- 材质与字色也有主次。近白阅读面、彩色面与浮层应有可辨的分量差别；不要让所有区域都使用同样的透明度、圆角、亮边和阴影。辅助文字可读性合格，不等于整页配色和尺度已经协调。页面说明服务用户任务，设计过程与实现说明放在评审材料中。
- 保持原有组件库与业务规则；需要复用时，将本项目采用的样式映射到现有主题和局部组件，不整包覆盖其他原型。只把已采用的项目决定按原流程写回交接卡。

## 并排看整体与局部

对照实际页面与选定参考，查看构图主次、颜色角色与面积、文字层级、疏密和表面关系。覆盖本轮相关的页面收尾、其他页面及布局变化点；已认可区域若受共享样式影响，也要复查。保持可解释的裁剪和比例，分别看整体关系与正常阅读尺寸下的局部，不以缩略图代替可读性检查。

实际画面与原先的设计解释冲突时，按可见问题重新选方案；不能因为“每种颜色都有用途”“图形对应真实数据”就维持整体效果不好的实现。

视觉改版按相关差距复查，以下问题用于判断画面，不要求新增一套检查报告：

| 观察对象 | 需要辨别的差距 |
| --- | --- |
| 构图与节奏 | 主区是否有明确分量；次要区是否只是均匀排卡；空白是在组织阅读，还是让内容松散 |
| 色彩与字色 | 同一色相的累计面积是否压平中性、冷暖和深浅关系；文字是否也被整页染色 |
| 图形与信息 | 图形面积是否符合信息价值；是否为三项数字增加大块重复形状；趋势或构成能否更快看懂 |
| 表面与尺度 | 材质是否区分层级；主数字、正文、注释及控件在正常阅读尺寸下是否协调 |

区分界面自身与人物摄影、设备倾斜、景深或展示镜头带来的效果。只有图片时，不反推未经证实的字体、CSS 数值、交互或业务效果。外部灵感图未被确认为验收目标时，比较用于提出设计建议，不要求逐像素复刻。

结论写清可见现象、影响、建议和仍有的差距；区分业务适配、尚未达到目标和待用户决定。审美建议单列，不仅因偏好不同就定为缺陷。功能、对比度和截图回归检查只证明各自事项，检查数量也不证明视觉提升。实际对照仍暴露明显差距时，在已授权范围内处理，或明确保留该判断，不用“业务不同”“不能造数据”替代可解决的设计问题。

用户否定某一版的观感后，更新那一版的采用状态，并保留此前认可的具体范围；不继续把已否定版本写成成功经验，也不据此生成全项目的颜色禁令。方法文件更新、文字推演或文件校验通过，都不能作为审美已经提高的证明。

## 涉及动效时实际操作

静态图不能证明动效，展示视频中的镜头也不等于界面交互。设计时说明触发、作用与终态，时长、缓动和幅度按任务选择。实际检查响应、连续快速切换、取消或关闭返回，以及减少动态时的表现；CSS 与 JavaScript 都要覆盖相关变化，最终状态与最后一次操作一致。

截图回归可能禁用动画，不能据此报告动效通过。只读静态评审时保留这一证据边界；实现或修改动效时，沿用主流程验证受影响操作与性能，不因本说明重复全量验收。
