# 浅色界面研究与试验经验

根据 2026-10-23 的来源观察和本机试验整理。以下是可复用的研究结论；本机演示的配色、尺寸与动效参数属于该案例候选，不构成通用要求。[补充看图页](index.html)随包保存3张来源截图与1张用户提供的示例，出处见[来源清单](references/来源.json)；演示源码和本机验收记录未随包分发。

## 试验中应保留的经验

- “浅色”不能推导出绿色品牌、单一主色或统一低饱和。先定义背景、阅读、操作、状态和数据的颜色角色，再选择具体颜色；区域色不自动代表成功、异常或选中。
- 用实际中文指标、长名称、多位数和单位检查层级。保留比较口径与完整数据入口，区分零值、尚未采集、业务为空、加载与失败。
- 用户认可一个区域，只保留那个区域的已确认决定；后续页面与改动需要各自检查。页面整体、局部正常阅读尺寸和受影响窄屏应分别对照。
- 几何、对比度、无溢出和功能检查通过，不能代替对颜色关系、材质和整体观感的判断。说明仍有差距与具体建议，不用自评分代替用户认可。
- 动效应解释触发与状态变化。快速切换、关闭或取消后不留下旧动画和错误终值；减少动态同时覆盖 CSS 与 JavaScript。截图回归禁用动画时，不能据此声称动效通过。
- 组件库、业务口径和已确认品牌继续沿用。将采用的样式映射到项目主题与局部组件；试验中的 tokens 和示例布局无需整包覆盖其他原型。

原作展示、实现候选、运行检查和用户认可分别记录。需要查看本机演示的当前版本与局部认可范围时，按项目交接卡定位 `设计参考/浅色界面/`；本页不将那一版本声明为通用完成标准。

## 2026-10-24 试验复盘补充

本机后续候选经用户反馈“绿色有点多，视觉不如对照”。这次结果说明：参考关系能被说清、功能能运行，仍可能做不好画面。以下提醒来自该次失败，不构成所有页面的配色限制。

- 为导航、字色、图表、点阵和背景分别赋予绿色用途，叠加后仍会让整页偏绿；要看累计面积与色彩关系，不能只看局部角色是否说得通。
- 大组高度接近的双柱与规则点阵虽然对应了数据，却增加了重复形状的分量。图形应服务比较与判断，数据准确和表达合适分别检查。
- 合并主卡、增加毛玻璃和减少框线，都不自动形成版面节奏。先核对主区与辅助区、文字与空白之间的分量，再扩展样式。
- 已通过的尺寸、焦点、周期切换和文件检查继续有效，但不能证明视觉成功；用户否定的版本保留为候选与反例，不写成已认可设计。
