# 浏览器检查与截图对比

使用附带浏览器脚本时读取。本脚本检查 `prototype.browser.json` 登记的操作、结果、存储和截图；未登记的页面、状态与异常，需要补场景或另行实际操作检查。

## 固定哪些条件

场景继续使用 `schemaVersion: 1`。旧配置可以读取；省略环境设置时，默认使用中文、上海时区、浅色和 1 倍像素比：

```json
{
  "schemaVersion": 1,
  "environmentId": "windows-local",
  "environment": {
    "locale": "zh-CN",
    "timezoneId": "Asia/Shanghai",
    "colorScheme": "light",
    "deviceScaleFactor": 1,
    "fixedTime": null
  },
  "scenarios": []
}
```

示例只展示配置结构，实际必须填写场景。

- 每个场景填写固定的页面宽高（`viewport`）、数据、操作和存储条件。
- 页面使用当天日期时，将固定时间（`fixedTime`）填写为带时区的 ISO 时间，例如 `2026-01-01T00:00:00.000Z`。没有固定日期的需要时保留 `null`；此时当前时间仍真实变化。
- 固定时间只影响日期读取，定时器继续运行，避免把异步业务一并暂停。时间推进类产品应使用项目自己的场景，不套用固定日期。
- 使用锁文件对应的 Chromium；字体由项目资源和运行环境固定。脚本会等待字体加载及画面稳定，但不会自动安装字体。
- 结果记录浏览器版本、操作系统版本、处理器架构及上述环境选项。环境不同先恢复原条件，或为新环境另建参考，不能直接覆盖原记录。

环境名称（`environmentId`）可用 `PROTOTYPE_BROWSER_ENVIRONMENT` 指定。命名环境分别保存在 `test-baselines/browser/<environmentId>/`；省略或使用 `default` 时沿用原来的 `test-baselines/browser-results.json` 和 `test-baselines/screenshots/`。性能检查的环境设置仍独立管理。

## 登记操作

支持的动作包括：

- 清空 `sessionStorage` 或 `localStorage`、刷新、等待、点击、输入和原生选择框选择。
- 悬停（`hover`）、聚焦（`focus`）和按键（`press`）；按键需填写 `key`，例如 `Tab`、`Enter` 或 `Escape`。
- 检查文字（`assertText`）、显示（`assertVisible`）、隐藏（`assertHidden`）、可操作（`assertEnabled`）和焦点（`assertFocused`）。

异步结果先等待本次输入对应的结果，再断言。仅等待页面框架不能证明操作完成。Ant Design 的自定义下拉按实际点击与按键登记，不将原生 `selectOption` 直接套到所有组件。

每个场景保存一张最终状态截图。需要比较悬停、展开等多个外观时，分别登记场景；不要把未截图的中间状态报告为已完成截图检查。场景 ID 和截图文件名各自唯一。

## 截图如何比较

脚本先等待字体和连续画面稳定，截图时禁用动画；这只影响截图过程，不允许因此删掉产品中的正常动画。

截图由同一固定浏览器解码，再逐像素比较 RGBA 值。图片尺寸或任一像素不同就失败，默认没有容差。PNG 压缩或元数据不同但解码像素相同，不算页面变化。

结果目录与环境名称对应：

- `browser-results.json`：操作、存储和完整路径结果。
- `report.json`：状态、环境、像素变化数量和差异文件位置。
- 原场景名的 PNG：本次截图。
- `*.diff.png`：存在差异时生成，变化像素用红色标出。以当前报告中列出的文件为准，旧结果目录可能留有历史图片。

差异出现后先定位页面、环境、数据或时间问题，不临时扩大容差、屏蔽区域或覆盖参考。

## 首次记录和普通检查

首次制作先确认页面符合本轮需求，再执行：

```sh
pnpm run build
pnpm run baseline:browser
pnpm run test:browser
```

记录命令的参数只表明执行意图，不能代替用户授权。初次制作已在任务范围内时不再重复询问；已有页面只有已确认的产品变化才更新受影响参考。更新前会保留旧结果和截图。

普通检查运行 `pnpm run test:browser`，只读取参考。缺参考、环境不一致、操作失败或截图变化均不通过。完整交付中的 `verify:release` 已包含此检查，不另行重复。

## 采用旧浏览器参考

旧结果使用 `schemaVersion: 1`，没有环境记录。新执行器在普通检查时会明确提示，不能把未知环境报告为已核对。

在改前页面和数据仍可恢复、环境与旧版一致时执行：

```sh
pnpm run test:browser --adopt-legacy-environment
```

该命令先对比旧操作结果、存储和旧截图。全部一致后，保留旧记录并补充当前环境与完整路由；不替换旧截图。存在差异则失败并保持旧参考。采用后再运行一次普通检查，确认新格式可正常比较。

它只用于补充缺失环境记录，不能用来接受产品变化。旧结果只保存路由的 hash 部分，补充完整路径前还需对照改前场景配置核对路由；脚本不能证明旧记录中没有保存的信息。浏览器配置仍为版本 1，结果文件升级为版本 2，两者不要混淆。

## 脚本改动如何验证

修改检查机制时验证正常情况、能否识别真实失败，以及旧配置如何处理。像素比较需要同时覆盖“编码不同但像素相同”“一个像素变化”和“尺寸变化”。环境设置需要在真实浏览器核对语言、时区、像素比和固定日期，并确认定时器与刷新仍正常。

测试使用隔离页面和合成数据。原工程截图与性能参考保留；工具测试通过后，仍要检查本轮真实原型的相关场景。
