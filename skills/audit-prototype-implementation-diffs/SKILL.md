# 原型与研发实现差异走查

## 确定适用范围

仅在同时具备“目标基线”和“当前实现”，且任务重点是二者差异时使用本 Skill。

用于启发设计的外部作品不自动成为验收目标；仅希望借鉴配色、主次或质感时，使用视觉评审流程。用户已确认采用的具体要求可以作为对应范围的目标，不把整张参考图的内容与样式一并升级为必须实现的要求。

以下任务改用更匹配的工作流：

- 只评审一个产品的体验、易用性或 AI 交互设计，不与目标稿对版：使用 [交互体验评审](../audit-ai-interaction-design/SKILL.md)。
- 用户要求制作、修改或修复原型：使用 [制作与修改交互原型](../build-interactive-prototype/SKILL.md)；正式研发沿用项目工作流。本 Skill 可作为已授权修改前后的只读对版步骤。
- 用户要验证接口、数据库、模型、Agent、MCP 或端到端业务结果：使用运行链路或业务验收工作流。
- 用户要补齐需求定义或完整 PRD：先完成产品定义，不把原型界面反推成全部需求。

## 加载项目适配规则

先读取真实项目已有的 `AGENTS.md`、交接卡和用户指定材料，再查找专项规则。

从当前工作目录和用户明确提供的来源路径分别向上查找下列精确相对路径，找到后把其所在项目目录视为候选项目根目录：

`.agents/skill-profiles/audit-prototype-implementation-diffs/PROFILE.md`

多个候选指向不同项目时，优先使用与本轮当前实现最近的候选；仍不能唯一判断时先向用户确认。项目 `AGENTS.md` 已声明该适配文件必读但文件缺失时，停止任务并报告，不能静默降级到通用流程。找到适配文件后必须完整读取。

项目适配规则可以补充来源优先级、特定模块检查项、截图规格、交付模板和外部系统流程，但不得：

- 扩大用户本轮指定的模块或写入范围。
- 把界面证据升级为接口、数据或业务正确性的证明。
- 跳过登录、权限、外部写入和破坏性操作所需的授权。
- 降低本 Skill 的事实、证据和写后回读要求。

项目没有适配文件时，按本 Skill 的通用流程执行。

## 确认本轮范围

先从对话、项目材料和现场状态确认：

1. 本轮模块和明确排除项。
2. 目标基线及其版本或更新时间，并确认它是当前验收目标；“最新版”这一称呼本身不等于已经确认。
3. 当前实现环境、分支或版本。
4. 需要构造的关键页面状态。
5. 本轮用途及交付形式；未要求文件或外部交付时，在当前对话给出差异清单。需要报告时按当次需求决定形式，可沿用项目默认位置或自行选择合适的本地文件名，不要求用户先提供精确路径。

只有缺失信息会改变比较对象、范围、目标状态或交付用途时才询问用户。连续复验时，先核对来源版本、模块和已有证据是否变化；只复查新增问题、未通过项和受改动影响的状态，不机械重做全量走查。同一任务涉及体验评审、制作或反馈时，沿用同一清单、条目编号与来源定位，补充当前侧和目标侧事实；分别说明判断依据，共用仍覆盖当前版本与状态的检查结果，不重复跑一套流程。

## 读取真实来源

1. 先加载目标基线，再加载当前实现；记录各自的来源、版本、时间或可识别标记。逐条记录差异时统一按“当前事实 → 目标事实”的顺序表达，避免把加载顺序与交付写法混淆。
2. 本地 HTML 或静态原型需要浏览器验收时，通过仅绑定 `127.0.0.1` 的本地 HTTP 服务访问。
3. 浏览器中的当前实现使用真实可访问环境和现有登录态；需要操作浏览器时，使用当前环境可用的浏览器控制工具并先读取工具文档；未指定浏览器时优先本机 Chrome，回退 Edge。
4. 比较双方时使用相同或可解释的视口、缩放、数据条件和页面位置。项目适配规则已明确本次规格时按其执行；与目标基线或其他规范冲突且影响判断时，标明待确认，不自行选择“更严格”的数值作为目标。
5. 先识别目标基线是静态图片或 PDF、静态 HTML，还是可交互原型。单张静态画面不能证明未展示的悬停、校验、保存反馈等状态；这些状态只能由可交互来源、明确规格或其他等价证据确认，否则标记待确认或验证受阻。
6. 单张截图不足以证明交互时，实际构造悬停、点击、展开、收起、新建、编辑、校验、取消、刷新、返回和直达链接等相关状态。默认保护真实数据；保存、创建、删除、发送、运行及自动保存等有实际影响的动作，先核对已有授权、测试数据、影响范围和恢复方式，已获授权不重复询问。已确认可恢复且不连接真实服务的隔离演示环境可构造相关状态；自动保存需在编辑前识别。
7. 必要时读取原型源码或当前前端实现辅助判断，但把“代码推断”和“页面实测”分开记录。

缺少完整来源、登录态或权限时，暂停受影响的结论并标记“验证受阻”；不用截图、旧版本或低质量替代来源冒充当前事实。现有登录态只证明可以访问，不等于获得查看敏感内容、提交数据或扩大操作范围的授权。

## 建立差异清单

按需读取 [走查检查表](references/walkthrough-checklist.md) 中相关维度，只选择本轮真实存在的模块和状态；全面对版时再用整表查漏。

在本轮范围内盘点目标基线与当前实现的功能、入口、字段、步骤、状态和反馈；可在现有清单中完成对照，不强制另交两份全量盘点表。按以下类型记录差异：

- `新增`：目标基线有、当前实现没有。
- `调整`：双方都有，但名称、位置、条件、流程、呈现或结果不同。
- `删除`：目标基线已移除、合并、停用或替代当前实现中的对象。

同时从当前实现反查本轮范围内的可见变化，确认目标要求或必要适配是否已有对应记录。还原基准已有能力不作为新增产品需求；样本补采、模拟安排和运行修复注明其性质。产品新增呈现与技术底座调整分别判断，不能从技术变化直接推导界面必须重做。

随后逐项盘点页面名、页签名、字段名、按钮名、弹窗标题、输入提示、说明、校验、空态和结果反馈。文案差异必须写成“当前值 → 目标值”，不能只写“调整文案”或只在截图中框选。

把观察结果区分为：

- `确认差异`：双方事实可直接观察，且当前实现与已确认目标不同。
- `合理实现增强`：走查目标状态时直接遇到、与本模块不可分割，且为可用性、安全或技术完整性所必需；作为单独建议，不冒充已确认原型要求或自动扩大修改范围，也不主动扩展成通用体验审计。
- `继续保证`：当前实现已经满足目标，仅在回归风险较高或用户要求保留时记录。
- `待确认`：目标基线有歧义或缺少产品、设计、研发决定。
- `验证受阻`：因来源、权限、环境或关键状态不可用而无法下结论。

原型中的 Mock 数据、固定文案或样例结果只证明界面目标，不证明真实业务能力已经定义或实现。

## 拆成可独立验收项

按“可以独立修改、独立复验”拆分条目：

- 同一原因、同一组证据和同一验收标准能够讲清的内容可以合并。
- 触发条件、状态变化、责任归属或验收结果不同的内容应拆开。
- 不按按钮数量机械拆分，也不把整页无关问题塞进一条。
- 已有条目可以准确覆盖新发现时补强原条目，避免重复。
- 每条必须写清当前事实、目标事实、建议动作和可观察的通过条件。

组织清单时参考 [证据与交付规范](references/evidence-output-contract.md)；用户或项目已有模板时，保持其字段和格式。局部清单可以合并字段，但不得丢失事实、目标、证据和验收四类信息；体验建议单列依据，不自动升级为目标要求。只有外部交付时才执行相应的写入与回读步骤。

## 准备成对证据

1. 当前实现与目标基线使用相近裁剪范围、缩放比例、数据条件和页面状态。
2. 静态差异通常各用一张图；交互差异要覆盖动作前后或其他关键状态。
3. 一组证据只突出一个可独立验收问题，图中文字必须清晰可读。
4. 截图、录屏、日志或源码证据都标明所属侧、模块、状态和获取时间。
5. 只有一侧可见时，不伪造成对证据；写清另一侧缺失原因和结论强度。
6. 构造证据遵守前述数据边界。没有必要授权时，只检查安全可见的状态；暂停依赖提交的结论并标记验证受阻，不以本地模拟代替真实结果。

## 交付与回读

默认在当前对话中交付；用户需要文件报告时按当次用途生成。只有用户已经明确外部系统、目标位置和本轮范围，且当前环境具备相应权限时，才执行外部写入。飞书反馈的处理状态回写配合 [处理飞书原型反馈](../iterate-prototype-from-feishu-feedback/SKILL.md)，不因本次走查自动改状态。

外部写入时：

1. 先读取目标范围，避免覆盖历史内容或重复记录。
2. 按用户确认的范围写入文字和证据，不顺带扩写其他模块。
3. 写后通过接口回读并通过可见页面检查图片、顺序、格式和持久化结果。
4. 明确失败且原因可修复时，在已授权范围内修正；超时或结果未知时先查询最新目标，确认是否已写入，不盲目重试或重复新增。缺少权限、无法确定结果，或同一原因反复失败且没有新证据时，暂停受影响写入并说明缺口，不把“调用成功”当成“交付完成”。

结束前复核：

- 本轮模块和来源版本准确。
- `新增／调整／删除` 与文案差异没有只画图不写要求。
- 每条的当前事实、目标、动作和验收标准完整。
- 成对证据方向正确、图文对应、关键状态齐全。
- 待确认项和验证受阻项没有被写成确认缺陷。
- 本轮不再需要的临时服务和标签页已关闭；保留用户原有资源、仍需访问的交付服务及必要证据。中间文件按项目回收规则处理，不擅自物理删除。

最终按实际结果汇报已确认差异、需保留的已满足项、待确认项、验证受阻项，以及实际完成的写入与回读；没有差异时说明检查范围和限制，不为填类别制造问题或完整合规清单。
