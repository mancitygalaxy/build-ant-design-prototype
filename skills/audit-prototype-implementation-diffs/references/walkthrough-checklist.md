# 原型与研发实现走查检查表

## 使用方法

先列出本轮真实存在的页面、功能和状态，再选择检查项。每项都先观察当前实现，再核对目标基线；没有差异且没有回归风险时，不需要写入交付清单。

## 通用检查维度

| 检查维度 | 需要确认的内容 |
|---|---|
| 页面结构 | 页面区域、主次关系、宽高、留白、滚动容器、固定区域和内容起始位置 |
| 信息架构 | 页面名称、字段、说明、顺序、分组、层级、长内容、空态和异常态 |
| 界面文案 | 页面名、页签名、字段名、按钮名、弹窗标题、输入提示、说明、校验和结果反馈 |
| 视觉呈现 | 颜色、字号、字重、间距、圆角、边框、阴影、图标、对齐和层级 |
| 品牌与图标 | Logo、素材来源、尺寸、描边、颜色、方向、基线、名称提示和不同状态的一致性 |
| 交互状态 | 默认、悬停、聚焦、选中、展开、收起、禁用、加载、成功和失败 |
| 操作边界 | 点击行、名称、图标、按钮和空白区域分别触发什么，动作范围是否明确 |
| 功能增删改 | 入口、按钮、字段、步骤、状态、反馈和替代路径有哪些新增、调整或删除 |
| 表单行为 | 新建、查看、编辑、保存、取消、校验、只读、默认值和派生字段 |
| 状态连续性 | 刷新、返回、切页、直达链接和重新进入后，上下文是否符合目标 |
| 结果反馈 | 成功、失败、危险操作、异步过程、重试和外部系统写入的反馈 |
| 数据边界 | 长文本、长 ID、长 URL、满列表、最后一项、空数据、异常数据和权限差异 |
| 响应与可访问性 | 目标明确覆盖的视口、缩放、键盘操作、焦点、对比度和可读性 |

响应式和可访问性只有在目标基线、产品规范或用户范围包含时才写成原型差异；否则可单独标为合理增强或待确认。

## 状态构造顺序

1. 默认进入页面。
2. 悬停和聚焦可操作元素。
3. 选择当前项。
4. 展开和收起分组、下拉框、抽屉、弹窗或浮层。
5. 进入新建、查看或编辑。
6. 按主说明的数据边界触发校验、取消和错误反馈；真实写入先核对已有授权，自动保存需在编辑字段前识别。
7. 检查危险操作的确认提示，不执行未经授权的破坏性动作。
8. 刷新页面。
9. 通过当前地址直接进入。
10. 切换到相邻页面后返回。

只构造与本轮模块和差异判断有关的状态，不为凑完整度虚构场景。

## 功能增删改盘点

分别制作目标基线和当前实现的功能清单，再逐项对照：

- `新增`：确认入口位置、出现条件、进入后的页面或浮层、可完成动作和结果反馈。
- `调整`：确认调整前后在名称、位置、字段、条件、流程、状态和结果上的变化。
- `删除`：确认原对象不再出现、是否有替代路径，以及界面上可观察到的历史数据和既有操作影响；需要接口、数据或业务证据的影响另行验证。

目标新增的按钮或辅助能力必须同时出现在文字要求和验收标准中，不能只靠截图表达。

## 界面文案盘点

- 记录当前文案与目标文案，保留大小写、空格、标点和术语差异。
- 按钮与弹窗成组核对：入口按钮、弹窗标题、字段名、输入提示、取消、确认、关闭和完成反馈。
- 搜索成组核对：搜索范围、输入提示、输入与清空行为、无结果空态，以及切换范围后的状态。
- 文案差异写成“当前值 → 目标值”，同时进入调整要求和验收标准。

## 状态与持久化判断

- 页面刷新前后的结果分别观察，不用内存态证明持久化完成。
- 只有界面可见状态时，只对界面层下结论；接口或服务端事实另行验证。
- 目标稿没有表达的错误、权限或极端数据状态，不自动写成原型缺陷，可按必要性标为合理增强建议或待确认；建议不自动成为已确认的修改要求。
- 当前实现已有且正确的状态不列缺陷；有明确回归风险时写“继续保证”。

## 视觉精度边界

- 有设计标注、Design Token 或项目规范时，按可核验的精确值比较。
- 只有截图时，记录可观察的颜色、间距、字号或对齐差异，不臆造像素值、色值或容差。
- 精确目标会影响研发实现但当前来源没有提供时，标记待设计确认。

## 证据强度

- 双方同状态实测并有成对证据：可以确认差异。
- 一侧可实测、另一侧只能由源码或说明推断：写清推断来源和限制。
- 一侧无法进入或关键状态无法构造：标记验证受阻。
- 目标基线存在多个版本或相互冲突：停止拍板，标记待产品或设计确认。
