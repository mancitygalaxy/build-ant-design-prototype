# 证据与交付规范

## 默认交付字段

用户或项目没有既定模板时，按需要使用下列字段。它们说明每条应保留的信息，不强制局部清单展开成宽表；报告是否生成及其形式按当次需求。

| 字段 | 内容 |
|---|---|
| 编号 | 稳定、可引用的差异编号 |
| 模块与状态 | 页面、功能区域和触发状态 |
| 变更类型 | 新增、调整、删除或不适用 |
| 结论状态 | 确认差异、合理增强、继续保证、待确认或验证受阻 |
| 当前实现 | 已实际观察到的事实 |
| 目标基线 | 原型、设计稿或产品基线表达的目标 |
| 调整要求 | 需要增加、修改、移除或继续保证的内容 |
| 验收标准 | 对象、动作、关键状态和可观察的通过结果 |
| 当前证据 | 当前实现侧的截图、录屏、日志或源码位置 |
| 目标证据 | 目标基线侧的截图、页面、节点或源码位置 |
| 备注 | 版本、来源、责任归属、阻塞或推断边界 |

同一条目必须能够独立修改和独立复验。项目已有表格列较少时，可以把多个字段合并进一个结构化单元格，但不能丢失当前事实、目标、证据和验收标准。

## 文字要求

- 当前实现只写已经观察到的事实，不用“应该”“似乎”代替证据。
- 目标基线写清目标结果；有歧义时标明待谁确认。
- 调整要求使用具体动作，不写“优化一下”“保持一致”等空泛描述。
- 文案差异写成“当前值 → 目标值”。
- 验收标准至少包含对象、动作或条件、关键状态和最终可见结果。
- 界面证据不能证明接口、数据、权限或业务链路正确时，明确写出验证边界。

## 截图与证据配对

- 当前侧与目标侧保持相近视口、缩放、裁剪、数据和状态。
- 文件名或说明包含差异编号、所属侧和状态，避免写入时放反。
- 静态问题通常一侧一张图；交互问题覆盖动作前后或最关键的两个状态。
- 一张图只突出一个条目的核心差异，多个条目共用证据时说明复用关系。
- 标注颜色由项目适配规则决定；没有规则时，两侧使用稳定且不同的颜色，并在交付物中注明图例。
- 读取接口返回的空图片字段不能单独证明图片缺失或存在，外部表格中的图片要以刷新后的可见页面为准。

## 外部交付回读

外部写入完成后同时做结构回读和视觉检查：

1. 条目数量、编号、模块、文字和列顺序正确。
2. 当前证据与目标证据均存在，方向正确且与文字同行。
3. 长文本、换行、列宽和行高可读，没有截断、遮挡或字面量换行符。
4. 待确认、验证受阻和推断边界没有丢失。
5. 刷新或重新打开后，文字和证据仍然存在。

明确失败且原因可修复时，在已有授权范围内修正。结果未知或超时时，先读取最新目标并核对条目、文字与图片是否已经存在，不直接重复新增或覆盖。缺少权限、结果始终无法确定，或同一失败反复出现且没有新证据时，暂停受影响写入并报告缺口；不要仅以接口成功响应作为验收结论。
